| **核心概念** | **功能描述** | **快捷键 (视频作者配置)** | **默认快捷键 (作为参考)** |
| --- | --- | --- | --- |
| **Session (会话)** | 最大的容器，通常一个项目对应一个 Session，可以包含多个 Window。 | | |
| | 创建新 Session | `Alt + Shift + S` | `tmux new -s <session_name>` |
| | 切换 Session | `Ctrl + 数字键` 或 `F1, F2...` | `Ctrl+b s` |
| | 重命名当前 Session | `Prefix + .` | `Ctrl+b $` |

| | 重连 (Attach) | (未在视频中明确说明快捷key) | `tmux attach -t <session_name>` |
| **Window (窗口)** | Session 内的容器，类似于浏览器中的标签页，可以包含多个 Pane。 | | |
| | 创建新 Window | `Alt + O` | `Ctrl+b c` |
| | 切换 Window | `Alt + 1, 2, 3...` | `Ctrl+b <窗口编号>` |
| | 调整 Window 顺序 | `Alt + LB/RB (U/O)` | `Ctrl+b .` |
| | 关闭当前 Window | `Alt + Shift + Q` | `Ctrl+b &` |
| | 重命名当前 Window | `Prefix + ,` | `Ctrl+b ,` |
| | 将 Window 移动到其他 Session | `Prefix + 数字键` | 不常用 |
| **Pane (窗格)** | Window 内的容器，即分屏，一个 Window 可以分割成多个 Pane。 | | |
| | 向指定方向创建新 Pane | `Prefix + 上/下/左/右` | `Ctrl+b %` (垂直), `Ctrl+b "` (水平) |

### TMUX：AI 时代开发者的必备神器

正如视频中所强调的，随着 AI 编码能力的日益强大，开发的瓶颈已不再是写代码本身，而是如何高效地管理和调度多个 AI 同时处理不同的开发需求。TMUX (Terminal Multiplexer) 正是解决这一问题的利器。它本质上是一个终端复用器，允许您在一个终端窗口中创建和管理多个独立的终端会话。

#### 1. TMUX 的核心概念

为了更好地理解 TMUX，我们需要了解它的三个核心层级概念，从大到小依次是：

*   **Session (会话):** 这是 TMUX 中最大的容器。你可以为每一个独立的项目或任务开启一个 Session。例如，一个用于前端项目，一个用于后端API，另一个用于数据库管理。不同 Session 之间是完全隔离的。
*   **Window (窗口):** 在每个 Session 内部，你可以创建多个 Window，这就像浏览器的标签页一样。例如，在前端项目的 Session 中，你可以一个 Window 用于运行开发服务器，一个 Window 用于编写代码，另一个 Window 用于运行测试。
*   **Pane (窗格):** 这是 TMUX 最直观的功能之一。你可以在一个 Window 内创建多个 Pane，也就是分屏。这允许你同时查看和操作多个命令行界面。例如，左边用 AI Agent 编写代码，右上显示 Git 状态，右下实时运行项目预览。

#### 2. 为什么 AI 辅助编程需要 TMUX？

*   **并行处理与进度管理:** 现代开发常常需要同时处理多个任务。你可以为每个任务（比如修复一个 bug、开发一个新功能）开启一个独立的 TMUX 工作区（Session 或 Window）。每个工作区内可以配置好对应的 AI Agent、代码、测试和预览环境。这使得你可以同时让多个 AI 并行工作，并通过切换工作区来清晰地管理每个任务的进度，避免混淆。
*   **永不中断的会话 (Detach & Attach):** 这是 TMUX 的一个革命性功能。你可以随时从一个 TMUX 会话中“分离”（Detach），关闭你的终端或断开 SSH 连接，但其中运行的所有进程（如 AI 模型的推理、长时间的编译任务）都会在后台继续运行。当你准备好回来时，只需重新“连接”（Attach）到那个会话，所有的窗口、窗格布局和正在运行的程序都将原封不动地恢复到你离开时的状态。这对于远程服务器开发或运行耗时任务至关重要。
*   **强大的自动化与脚本能力 (API):** 视频中提到了 TMUX 提供的三种强大 API，这是其从一个简单的工具变为一个工作流自动化平台的关键：
    *   **终端操控 API:** 允许脚本或 AI 直接控制 TMUX 中的终端，向其发送指令、读取输出。这意味着 AI 不仅能生成代码，还能直接在终端中执行编译、测试、运行等一系列操作，实现真正的自动化开发。
    *   **窗口布局 API:** 允许你通过脚本一键创建和配置复杂的工作区布局。例如，你可以编写一个脚本，在启动新功能开发时，自动创建一个新的 Git 分支，并以此命名一个新的 TMUX Window，同时在其中自动划分好窗格，分别启动 AI Agent、Git 监控和项目服务器。
    *   **钩子 (Hooks):** 这是一种事件监听机制。你可以让 TMUX 在特定事件发生时（如切换窗口、关闭窗格）自动执行某个命令或脚本。视频中举例，利用钩子可以实现在切换 TMUX 工作区时，浏览器自动切换到对应项目的预览页面，极大地提升了工作流的流畅性。

#### 3. 如何开始使用 TMUX？

1.  **安装:** TMUX 在大多数 Linux 和 macOS 系统中都可以通过包管理器轻松安装。
    *   **macOS (Homebrew):** `brew install tmux`
    *   **Ubuntu/Debian:** `sudo apt-get install tmux`
    *   **CentOS/RHEL:** `sudo yum install tmux`

2.  **启动:** 在终端中输入 `tmux` 即可启动一个新的 TMUX 会话。

3.  **配置文件:** TMUX 的强大之处在于其高度的可定制性。所有的配置都存储在用户主目录下的 `.tmux.conf` 文件中。你可以像视频作者一样，根据自己的习惯定制快捷键、界面外观等。刚开始时，可以寻找一些社区中流行的配置文件作为起点，然后逐渐修改成自己顺手的样子。
