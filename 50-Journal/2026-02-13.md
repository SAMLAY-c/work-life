## 📚 Remotion Skills 完整使用教程

### 一、什么是 Remotion Skills?

Remotion Skills 是一套"AI 知识包",让 Claude Code 学会如何正确写 Remotion 代码。这些技能对 AI 代理如 Claude Code、Codex 或 Cursor 非常有用。

**核心价值:**

- 🎯 让 AI 理解 Remotion 的最佳实践
- 🚀 避免常见错误(如动画参数顺序、帧数计算等)
- 📦 包含 30+ 个规则文件,涵盖动画、音频、3D、字幕等

### 六、实战案例:创建 10 秒产品发布视频

#### 1. 描述需求(自然语言)

在 Claude Code 中输入:

```
创建一个 10 秒的产品发布视频:

场景 1 (0-3秒):
- 深色背景
- 产品名称 "DevFlow" 从透明淡入
- 加发光效果

场景 2 (3-7秒):
- 产品名称滑到左边
- 右边依次出现 3 个特性:
  1. "⚡ 10x Faster"
  2. "🔒 Enterprise Security"
  3. "🌍 Global CDN"

场景 3 (7-10秒):
- 全部元素淡出
- CTA 按钮 "Get Started" 放大出现
- 加脉冲动画
```

#### 2. Claude 自动生成文件结构

```
src/
├── ProductLaunch/
│   ├── index.tsx        # 主组件
│   ├── Intro.tsx        # 场景 1
│   ├── Features.tsx     # 场景 2
│   └── CTA.tsx          # 场景 3
└── Root.tsx             # 注册 Composition
```

#### 3. 生成的代码示例

```tsx
// src/ProductLaunch/index.tsx
import { AbsoluteFill, Sequence } from 'remotion';
import { Intro } from './Intro';
import { Features } from './Features';
import { CTA } from './CTA';

export const ProductLaunch: React.FC = () => {
  return (
    <AbsoluteFill className="bg-slate-900">
      {/* 场景 1: 0-90 帧 (3秒) */}
      <Sequence from={0} durationInFrames={90}>
        <Intro />
      </Sequence>
      
      {/* 场景 2: 90-210 帧 (4秒) */}
      <Sequence from={90} durationInFrames={120}>
        <Features />
      </Sequence>
      
      {/* 场景 3: 210-300 帧 (3秒) */}
      <Sequence from={210} durationInFrames={90}>
        <CTA />
      </Sequence>
    </AbsoluteFill>
  );
};
```

#### 4. 实时预览 & 迭代

打开 `http://localhost:3000` 查看效果。

**不满意?继续用自然语言调整:**

```
"发光效果太强了,减弱 50%"
"特性出现的间隔改成 0.5 秒"
"CTA 按钮换成蓝色"
```

#### 5. 渲染输出

```bash
npx remotion render ProductLaunch out/product-launch.mp4
```

### 八、进阶技巧

#### 1. 批量生成视频

```tsx
// 参数化组件
export const PersonalizedVideo: React.FC<{
  userName: string;
  productName: string;
}> = ({ userName, productName }) => {
  return (
    <AbsoluteFill>
      <h1>Hi {userName}, meet {productName}</h1>
    </AbsoluteFill>
  );
};
```

批量渲染脚本:

```typescript
const users = [
  { userName: 'Alice', productName: 'DevFlow' },
  { userName: 'Bob', productName: 'DevFlow' },
  // ... 1000 个用户
];

for (const user of users) {
  await renderMedia({
    composition: 'PersonalizedVideo',
    inputProps: user,
    outputLocation: `out/${user.userName}.mp4`,
  });
}
```

#### 2. 保持简单

从测试中学到的最重要经验:保持简单。当你尝试做复杂的事情——很多移动元素、重叠动画、花哨转场——很快就会变得混乱。

**建议:**

- ✅ 从简单动画开始(文字淡入、滑动)
- ✅ 逐步迭代增加效果
- ❌ 不要一次做太多复杂效果

### **二、高质量内容创作流程**

#### **第一步：从低质量提示到高质量提示**

**❌ 低质量提示示例：**

- 没有定义"好的演示文稿"标准
- AI不知道你的逻辑和哲学

**关键洞察：** AI模型是由对"优秀标准"有不同理解的人训练出来的，你必须提供清晰的指导和背景。

---

#### **第二步：提炼优质理念**

**实操案例：** 从YouTube视频《如何演讲》中提取演讲理念

1. **获取素材**
    
    - 复制YouTube视频链接
    - 使用字幕提取工具获取完整文字稿
    - 粘贴到文档中
2. **AI分析**
    
    - 提示词：_"请分析这份字幕，提炼出视频中关于如何构建演示文稿的所有重要内容，用简洁的要点呈现，忽略其他无关部分"_
    - ChatGPT思考20秒后生成结构化大纲
3. **本地保存**
    
    - 创建"写作演示的哲学.md"文件
    - 保存在Obsidian中，便于复用

#### **第三步：基于理念的深度创作**

**为什么不直接用AI生成内容？**

> "如果不是基于我自身的经历，那他甚至都不值得展示"

**解决方案：让AI挖掘你的想法**

1. **上传理念文档**到ChatGPT
2. **提示词模板：**
    
    ```
    基于这个创建演示文稿的理念，以及其中定义的结构，
    我希望你逐一提问，针对我即将谈论的主题[具体主题]，
    提出5个问题来了解我对这个主题的看法。
    在收集好这些问题之后，就可以按照指南来准备演示文稿。
    ```
    
3. **AI提问示例：**
    
    - 你的核心理念是什么？
    - 你希望观众内化的基本信念是什么？
    - 人们至今未动手开发应用的真实原因是什么？
4. **用语音快速回答**（Whisper Flow）

### **三、关键工具选择逻辑**

#### **为什么用本地笔记而非ChatGPT项目？**

|**ChatGPT项目**|**本地存储(Obsidian)**|
|---|---|
|仅限ChatGPT使用|可在所有AI工具间复用|
|无法用于编程工具|可直接拖入Cursor等代码工具|
|云端存储|完全掌控数据|

**核心优势：** 当涉及源代码和高级工具时，本地保存"极其有价值"

---

### **四、从流程到软件的转化**

**作者的愿景：**

1. 当前流程虽有效，但**每次都复制YouTube内容太繁琐**
2. **整套流程可转化为软件**，实现即时可用
3. 最终目标：开发一个**自动化工具**
    - 输入理念 → 自动提问 → 生成多平台内容
    - 让"无编程基础的人"也能创建应用

---

### **五、核心价值观**

#### **关于"无代码编程"的信念：**

> **"任何人都能做到"**

- 分为编程让软件体验对每个人触手可及
- 只要理解基本逻辑和主要AI工具
- 就能像**搭乐高积木**一样组合创造高质量应用

#### **人们为什么不动手？**

1. **没花时间摸索工具**（投入几小时就能改变生活）
2. **没有具体要解决的问题**
3. **没意识到自己也能做到**

**解决方案：** 花5小时学习，就能开始打造真正有用的工具

### **六、可复用的方法论**

```
优质内容创作公式：
理念提炼 → 本地保存 → AI提问 → 语音回答 → 生成内容 → 工具化流程
```

**适用场景：**

- 视频脚本创作
- 演讲稿准备
- 课程设计
- 产品文案
- 任何需要深度思考的内容创作

## 详细内容解析

### 1. AI原生应用开发挑战

**核心问题：最后5%的困境**

开发者分享了一个普遍现象：使用AI辅助编程（Vibe Coding）时，95%的功能可以在2小时内快速实现，但剩下的5%却会无限期延续。这揭示了当前AI辅助开发的核心矛盾。

**实际案例：企业分析应用**

展示了一个正在开发的企业分析工具：

- **功能**：分析公司背景、财务数据、领导团队
- **数据源**：使用Claude API、Cavii、Amplify
- **挑战**：
    - 数据准确性问题严重
    - 幻觉现象频繁出现
    - 网络搜索功能不稳定
    - 需要反复调试和修复

**个性应用案例**

另一个展示的是性格测试应用：

- 30分钟问卷生成100+页详细报告
- 创建自定义AI助手（适配ChatGPT、Claude等）
- 生成临床级PDF报告
- 创建个性化交流卡片
- 设计质量高，不像典型的AI生成界面

**关键启示**

开发者意识到需要：

- 在初期设置好护栏
- 完善日志记录系统
- 提供AI自我调试和修复的工具
- 区分明确功能开发 vs 开放式目标

---

### 2. Agent Native架构

**什么是Agent Native？**

Agent Native（原生代理）架构强调应用应该"像AI思考的方式"来设计，而不是传统的请求-响应模式。

**架构转变的必要性**

传统架构问题：

- AI没有被训练成传统方式思考
- 需要引导AI按照自然方式工作
- 传统架构限制了AI的能力发挥

**实践建议**

使用Compound Engineering插件：

- 让AI自我测试
- 持续运行直到成功
- 使用"原生代理审查"技能检查应用是否符合原生代理原则

**技术栈示例**

- **API调用**：Claude API
- **财务数据**：Cavii、Amplify
- **数据验证**：实际检查和少量爬取
- **架构模式**：需要让AI能够自主进行大量网络搜索直到找到所需信息

---

### 3. AI赋能企业战略规划

**Anthropic的2026年战略规划案例**

这是一个非常实际的企业应用案例：

**第一步：CEO撰写高层战略**

CEO Dan使用Claude协作完成：

- 明确公司定位："唯一需要订阅的AI边缘服务"
- 确定服务人群和实现方式
- 设定年度主题和目标

**第二步：Notion代理采访各部门**

CFO Brandon推动的创新实践：

- Notion代理（新功能，未广泛宣传）采访各部门负责人
- 询问上季度表现、本季度计划
- 验证如何与公司整体战略挂钩
- 提出尖锐问题帮助验证假设

**流程特点**

- 主要由Claude（通过Notion代理）完成文档撰写
- 部门负责人进行来回讨论和修正
- 所有内容集中在Notion中便于连接和查阅

**规模效益**

- 公司规模：20+人
- 让管理变得更轻松高效
- 刚刚触及表面，还有更多应用场景待开发

### 4. AI提升内部信息效率

**Discord内容挖掘案例**

开发者构建的创新工作流：

**背景** 想象如果今天重新做一份新闻简报会是什么样？传统方式已经过时。

**解决方案** 使用Claude Code（未来会发展为完整智能体）：

1. 遍历公司Discord的所有频道
2. 阅读所有讨论内容
3. 根据讨论生成故事建议
4. 发现新工具和新流程

**意外收获**

AI在处理Discord时：

- 发现当天Granola会议链接
- 自动阅读会议记录
- 向CEO汇报会议中的重要事项
- CEO原本完全不知道这次会议
- 能够立即采取行动

**价值体现**

"我有很多想了解的会议内容，现在就能获知这些信息"

- 不需要打扰他人
- 自动获取关键信息
- 及时发现需要介入的事项

**会议记录策略**

- 工具选择：Granola或Otter（视情况而定）
- 自动登录所有Zoom会议
- 文化预期：非私密会议应记录以便后续使用
- 逐步转向Notion（因为能连接所有内容）

### 5. AI变革管理与挑战

**成熟组织的挑战**

开发者提出的核心问题：

> "在成熟组织中的变革管理，简直不可能，像向墙跪地"

**具体困难**

1. **巨轮难转向**：组织按既定方向运行时很难改变
2. **人员差异大**：30位CEO级别人物，有些热爱AI，有些认为被夸大
3. **需要一对一沟通**：至少关键管理层需要个别沟通
4. **时间和资源限制**：如果非常忙碌或业务繁多，难以实现

**Anthropic的优势**

Dan表示"真的很幸运"：

- 所有高层都是AI原生思维
- 公司核心业务就是AI
- 自然筛选出全力以赴的人

**未来解决方案：定制化信息传递**

关键洞察：不同人被不同事物激励

**举例**：

- **销售团队**需要听到："2026年营收翻倍"
- **设计师**需要听到："推出最伟大项目，赢得苹果设计奖"

**AI的角色**

随着技术发展，可以：

- 真正定制信息内容
- 根据对方情况调整沟通方式
- 让管理变得越来越轻松

### 7. AI模型智能切换策略

**Open Plan模型**

```

```

- **Opus**：用于智能规划
- **Sonnet**：用于代码审查
- 根据需求动态自动切换模型

**优势**：

- 效率更高
- 获得Opus的规划能力
- 保持Sonnet的执行速度

**Sonnet 1M上下文**

对于大型代码库特别有用：

- 支持100万token上下文
- 即使代码库很大也能处理
- 提升了整体开发效率

**选型建议**

开发者的实践经验：

- 不同任务使用不同模型
- 让AI自动选择最合适的模型
- 平衡智能度和响应速度

**自主性的革命性提升**

## 核心要点总结

### 开发理念转变

1. **从传统架构到Agent Native**：让应用按AI思考方式设计

3. **护栏优先**：早期设置好日志、调试、自我修复机制

### 组织应用

1. **战略规划自动化**：AI协助从CEO到各部门的战略对齐
2. **信息流自动化**：从会议记录到内部沟通的智能提取
3. **定制化沟通**：根据不同角色调整信息呈现方式

### 工具选择

1. **模型动态切换**：Opus规划 + Sonnet执行
2. **跨设备协作**：移动端发起，桌面端完成，自动同步
3. **速度为王**：原生支持的工具在实际使用中优势明显

### 文化建设

1. **记录优先**：非私密会议都应记录
2. **变革管理**：需要一对一沟通和文化设定
3. **工具统一**：集中到Notion等平台便于连接所有内容

### 未来展望

1. **从自行车到直升机**：自主性的指数级提升
2. **千人组织可行**：AI让大规模个性化沟通成为可能
3. **今天创业的优势**：这些工具让小团队拥有大公司能力
