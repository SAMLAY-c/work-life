
## 1）请求路径怎么填（插件路径）

你现在填的是：

`//open.feishu.cn/open-apis/bitable/v1/apps/:app_token/tables/:table_id/records/:record_id`

### ✅ 规则（最重要）

1. **路径里用 `:xxx` 表示“路径参数占位符”**  
    例如 `:app_token / :table_id / :record_id`  
    这些必须在「输入参数」里也各建一个 **path_param**，名字要一致（app_token、table_id、record_id）。

2. **如果接口有 Query 参数**（比如 `user_id_type`、`ignore_consistency_check`）
    
    - 平台通常有两种做法：
        
        - A）在路径里手动拼：`...?user_id_type=:user_id_type&ignore_consistency_check=:ignore_consistency_check`
            
        - B）在「输入参数」里新增 query 参数（有的平台叫 query_param / query）
            
    - 你截图里暂时没配 query，那就先不加也能用（它们都是可选）。

## 2）输入参数怎么配（Input）

你截图里目前输入参数是：

- `record_id`（String, path_param）
    
- `fields`（Object, body）
    
- `Authorization`（String, header）
    
- `app_token`（String, path_param）
    
- `table_id`（String, path_param）
    

这里我给你一个“标准化配置表”（照抄就行）：

### A. Path 参数（path_param）

|参数名|类型|传入方式|说明|
|---|---|---|---|
|app_token|String|path_param|多维表格 app token（app_xxx / bascxxx / appbxxx 这种）|
|table_id|String|path_param|数据表 table id（tblsxxx）|
|record_id|String|path_param|记录 record id（recxxx）|

### B. Header 参数（header）

|参数名|类型|传入方式|说明|
|---|---|---|---|
|Authorization|String|header|**固定格式**：`Bearer tenant_access_token` 或 `Bearer user_access_token`|

> 你在平台里把 Authorization 作为输入参数没问题。调试时就填：  
> `Bearer t-xxxxxx`（tenant_access_token）

### C. Body 参数（body）

|参数名|类型|传入方式|说明|
|---|---|---|---|
|fields|Object|body|要更新的字段对象（增量更新）|

**fields 的结构必须是：**

```json
{
  "fields": {
    "字段名1": "值",
    "字段名2": 123
  }
}
```

> 注意：你平台里把 `fields` 直接作为 body 参数时，要确认它最终发出去是不是包了一层 `"fields": {}`。  
> 从你截图的 cURL 看，它是 `-d '{"fields":{}}'` ✅ 这是对的。

## 3）输出参数怎么配（Output）

你这个接口返回一般是：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "record": {
      "record_id": "...",
      "fields": { ... }
    }
  }
}
```

### ✅ 输出参数建议这样配（最实用）

|输出字段|取值路径（JSONPath 思路）|用途|
|---|---|---|
|code|`code`|是否成功（0=成功）|
|msg|`msg`|错误信息/提示|
|record_id|`data.record.record_id`|更新后的记录 id|
|record_fields|`data.record.fields`|返回的字段内容（可选）|

> 你在后续流程里一般只需要 `code` 和 `msg` 做判断；要回写或日志展示，再拿 `record_id / record_fields`。

## 4）平台自动生成的 cURL，你应该怎么看

你截图里生成的是类似这样（我补全一下 Header）：

```bash
curl -X PUT "https://open.feishu.cn/open-apis/bitable/v1/apps/:app_token/tables/:table_id/records/:record_id" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer xxx" \
  -d '{"fields":{}}'
```

### ✅ 你要做的三件事

1. 把 `:app_token / :table_id / :record_id` 替换成真实值
    
2. `Authorization` 填 `Bearer t-xxxx`
    
3. `fields` 里放你要更新的字段（字段名必须和表里列名一致）
    

例如：

```bash
-d '{
  "fields": {
    "文本": "HelloWorld",
    "数字": 100,
    "复选框": true
  }
}'
```

## 5）最容易踩坑的点（你后面一定会遇到）

1. **Authorization 少了 Bearer 前缀**
    
    - 必须是：`Bearer token`，不是只放 token
        
2. **Content-Type 要对**
    
    - 文档写的是 `application/json; charset=utf-8`
        
    - 平台里选 `application/json` 多数也能过；如果遇到 400，再改成带 charset 的完整值
        
3. **字段类型不匹配（1254015 / 125406x）**
    
    - 日期字段要毫秒时间戳
        
    - 多选要数组
        
    - 人员字段要数组对象（`[{ "id": "ou_xxx" }]`）并且和 `user_id_type` 一致
        
4. **路径参数名必须对齐**
    
    - 路径里用 `:record_id`，输入参数也必须叫 `record_id`  
        不然平台不会替换，最终请求会带着 `:record_id` 发出去 -> 必炸
