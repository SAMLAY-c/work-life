## 🧭 深度解析 (工程/产品/变现)
## 背景与核心痛点
传统CLI工具存在两大核心问题：1) AI输出信息缺乏结构化展示 2) 多步骤交互流程难以追踪。具体体现在：
- 邮件撰写时需要反复切换上下文
- 会议时间协商缺乏可视化日历
- 复杂决策（如机票比价）依赖文本描述

### 技术实现与架构
技术栈三层架构：
1. **执行层**：Bun运行时（替代Node.js）+ Tmux窗口管理
2. **AI层**：Claude Code作为核心推理引擎，通过`--billing-link`实现商用API调用
3. **呈现层**：
   - 基础版：基于Tmux的pane分割渲染
   - 增强版（Mac专属）：iTerm2 Apple Terminal Integration

关键配置指令：
- 插件安装：`claude plugins install canvas`
- Tmux初始化：`tmux new-session -s claude_canvas`

## 产品逻辑与Agent设计
采用『场景化Sub-Agent』设计模式：
1. **邮件Agent**：
   - 字段映射：From/To/CC/BCC → Tmux表格布局
   - 交互热键：`Ctrl+E`进入编辑模式
2. **日历Agent**：
   - 数据源：Google Calendar API → 终端甘特图
   - 冲突检测：红色区块标注
3. **旅行Agent**：
   - 多维度对比：价格/时长/座位 → ASCII艺术图表

## 实战应用与落地
典型工作流示例（邮件场景）：
