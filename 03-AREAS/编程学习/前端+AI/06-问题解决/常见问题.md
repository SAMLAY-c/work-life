# 前端+AI 常见问题集

> 使用AI生成前端代码时的常见问题和解决方案

---

## 🚨 AI生成代码问题

### 问题1：样式不符合预期

**症状**：
- 颜色不对
- 尺寸不对
- 间距不对
- 布局错乱

**原因分析**：
- 需求描述不够具体
- AI对某些术语理解不同
- 没有提供参考

**解决方案**：

#### 方案1：提供具体数值
```markdown
❌ "按钮大一点"
✅ "按钮的padding是16px 32px，字体16px"
```

#### 方案2：提供参考
```markdown
"参考Ant Design的Button组件样式，
但主色调用#007bff"
```

#### 方案3：分步骤描述
```markdown
"第1步：先做基础布局（Flex居中）
第2步：再添加颜色和尺寸
第3步：最后添加hover效果"
```

**预防措施**：
- 描述需求时使用具体数值
- 提供参考设计稿
- 使用标准术语（参考 [[前端术语表]]）

---

### 问题2：功能缺失

**症状**：
- 某个功能没有实现
- 边界情况没处理
- 交互逻辑不完整

**原因分析**：
- 需求描述不完整
- 没有说明边界情况
- AI遗漏了细节

**解决方案**：

#### 方案1：使用Checklist
```markdown
"请确保以下功能都实现了：
- [ ] 功能1
- [ ] 功能2
- [ ] 功能3
- [ ] 边界情况处理
- [ ] 错误处理"
```

#### 方案2：提供测试用例
```markdown
"这个组件需要通过的测试：
1. 正常情况：XXX
2. 空数据情况：XXX
3. 错误情况：XXX
4. 边界情况：XXX

请确保所有测试都能通过。"
```

#### 方案3：分轮次实现
```markdown
"第1轮：先实现核心功能
第2轮：我再告诉你边界情况
第3轮：最后处理错误情况"
```

**预防措施**：
- 描述需求前先列功能清单
- 考虑各种边界情况
- 提供完整的使用场景

---

### 问题3：代码质量差

**症状**：
- 变量命名不清晰
- 代码结构混乱
- 没有类型定义
- 缺少注释

**原因分析**：
- 没有说明代码规范
- AI默认生成简单代码
- 没有明确质量要求

**解决方案**：

#### 方案1：明确代码规范
```markdown
"请遵循以下代码规范：
1. 命名：组件用PascalCase，变量用camelCase
2. TypeScript：严格模式，所有类型明确定义
3. 注释：每个复杂函数要有JSDoc
4. 结构：Hooks → Handlers → Render

请生成符合规范的代码。"
```

#### 方案2：要求重构
```markdown
"功能是对的，但代码质量需要提升：

改进点：
1. 变量命名要语义化
2. 函数要单一职责
3. 添加TypeScript类型
4. 添加必要注释

请重构代码。"
```

#### 方案3：提供最佳实践
```markdown
"请使用React最佳实践：
- 函数组件 + Hooks
- 自定义Hook封装逻辑
- Props类型定义
- children模式

请生成符合最佳实践的代码。"
```

**预防措施**：
- 一开始就明确代码规范
- 提供参考的优秀代码
- 要求AI遵循最佳实践

### 问题4：性能问题

**症状**：
- 渲染慢
- 卡顿
- 不必要的重渲染

**原因分析**：
- 没有做性能优化
- 组件设计不合理
- 缺少必要的优化手段

**解决方案**：

#### 方案1：要求性能优化
```markdown
"请优化这个组件的性能：

需要实现的优化：
1. 使用React.memo避免不必要的渲染
2. 使用useMemo缓存计算结果
3. 使用useCallback缓存回调函数
4. 虚拟滚动（如果列表很长）

请说明做了哪些优化，性能提升了多少。"
```

#### 方案2：性能分析
```markdown
"请分析这个组件的性能瓶颈：
1. 哪里可能导致性能问题？
2. 如何优化？
3. 优化后性能提升多少？

请给出分析和优化后的代码。"
```

#### 方案3：对比优化
```markdown
"请生成两个版本：
1. 基础版本：功能实现
2. 优化版本：性能优化

并对比两个版本的性能差异。"
```

**预防措施**：
- 设计组件时考虑性能
- 大列表使用虚拟滚动
- 合理使用memo/useMemo/useCallback

### 问题5：技术栈不匹配

**症状**：
- 使用了错误的技术栈
- 版本不匹配
- API使用错误

**原因分析**：
- 没有明确说明技术栈
- AI假设了默认技术栈
- 版本混淆

**解决方案**：

#### 方案1：明确技术栈
```markdown
"请使用以下技术栈：
- React 18
- TypeScript 5
- Tailwind CSS 3.4
- React Hook Form 7

请确保API和版本都匹配。"
```

#### 方案2：提供项目配置
```markdown
"我的项目配置：
\`\`\`json
{
  "dependencies": {
    "react": "^18.2.0",
    "typescript": "^5.0.0"
  }
}
\`\`\`

请生成兼容这个配置的代码。"
```

#### 方案3：说明环境
```markdown
"项目环境：
- 框架：Next.js 14（App Router）
- 样式：Tailwind CSS
- 状态：Server Components

请生成符合Next.js 14的代码。"
```

**预防措施**：
- 一开始就明确技术栈
- 提供package.json
- 说明框架和版本

## 🔧 特定场景问题

### 场景1：响应式布局

**问题**：移动端显示错乱

**解决方案**：
```markdown
"请确保组件是响应式的：

断点：
- Mobile: < 768px
- Tablet: 768px - 1024px
- Desktop: > 1024px

要求：
- Mobile上占100%宽度
- Tablet上2列布局
- Desktop上3列布局

使用Tailwind的响应式类。"
```

### 场景2：表单验证

**问题**：验证逻辑不完整

**解决方案**：
```markdown
"请实现完整的表单验证：

验证规则：
1. 邮箱：必填 + 格式验证
2. 密码：必填 + 最少6位
3. 确认密码：必填 + 与密码一致

验证时机：
1. 失去焦点时验证单个字段
2. 提交时验证所有字段
3. 输入时清除错误提示

请使用react-hook-form + zod实现。"
```

### 场景3：异步数据处理

**问题**：loading/error状态处理不当

**解决方案**：
```markdown
"请处理异步数据的状态：

状态：
1. loading: 显示骨架屏/加载动画
2. error: 显示错误提示 + 重试按钮
3. success: 显示数据
4. empty: 显示空状态

请使用Suspense + Error Boundary实现。"
```

### 场景4：组件通信

**问题**：父子/兄弟组件通信混乱

**解决方案**：
```markdown
"请实现组件通信：

父组件 → 子组件：通过props
子组件 → 父组件：通过回调
兄弟组件：通过父组件中转

如果太复杂，使用Context或状态管理库。

请给出清晰的组件通信方案。"
```

## 💡 最佳实践

### Practice 1：渐进式开发

```
第1步：最小可用版本
  ↓
第2步：添加基础功能
  ↓
第3步：处理边界情况
  ↓
第4步：优化性能
  ↓
第5步：完善文档
```

### Practice 2：测试驱动

```markdown
"请生成代码前，先写测试用例：

测试用例：
1. 正常情况：XXX
2. 边界情况：XXX
3. 错误情况：XXX

然后生成能通过这些测试的代码。"
```

### Practice 3：文档先行

```markdown
"请先设计组件API：

期望使用方式：
\`\`\`jsx
<Component
  prop1={value1}
  prop2={value2}
  onEvent={handler}
/>
\`\`\`

然后生成实现这个API的代码。"
```
