# 需求描述模板

> 让AI生成符合预期的前端代码的Prompt模板

---

## 🎯 万能公式

```
【角色设定】+【任务目标】+【具体要求】+【技术栈】+【输出格式】
```

### 完整模板

```markdown
# Role
你是一个经验丰富的前端工程师，精通[技术栈]。

# Task
请帮我创建一个[组件类型]

# Requirements
## 功能需求
1. [功能1]
2. [功能2]

## 样式需求
- 颜色：[具体颜色值]
- 尺寸：[具体尺寸]
- 间距：[具体padding/margin]
- 效果：[hover/active等]

## 交互需求
- [交互1]
- [交互2]

## 代码规范
- 使用[具体技术栈]
- 命名规范：[驼峰/下划线等]
- 代码结构：[函数式/类组件等]

# Output
请输出：
1. 完整代码
2. 关键代码说明
3. 使用示例

# Reference
参考：[如果有参考图或链接]
```

## 📋 常用场景模板

### 场景1：创建简单组件

#### 按钮组件

```markdown
请帮我创建一个React按钮组件：

要求：
1. 支持三种类型：primary、secondary、danger
2. 支持两种尺寸：default、small
3. hover时背景色变深
4. active时按钮下沉
5. disabled时置灰且不可点击
6. 使用Tailwind CSS

代码要求：
- 使用函数组件 + TypeScript
- Props类型定义完整
- 代码有注释
```

#### 输入框组件

```markdown
请帮我创建一个Vue 3输入框组件：

功能需求：
1. 支持v-model双向绑定
2. 支持placeholder
3. 支持显示/隐藏密码（type=password时）
4. focus时边框高亮
5. 支持错误提示（红色边框+文字）

样式需求：
- 边框：1px solid #ddd，focus时变蓝色
- 圆角：4px
- padding：8px 12px
- 使用SCSS

代码要求：
- 使用<script setup>
- Props类型定义
- Emit事件定义
```

## 🔧 迭代优化技巧

### 当第一次生成不满意时

#### 方法1：分步骤描述

```markdown
第一次请求：
"创建一个按钮组件"

第二次请求（基于第一次）：
"请调整上面的按钮组件：
1. 圆角从4px改成8px
2. hover效果更明显一点
3. 添加loading状态"
```

#### 方法2：提供对比

```markdown
"你生成的按钮很好，但是：
- 颜色偏深，我想浅一点（当前#0056b3，改成#007bff）
- 阴影太重，减轻一点
- 字体要再大2px

请重新生成。"
```

#### 方法3：给出参考

```markdown
"参考Ant Design的Button组件：
https://ant.design/components/button-cn

但是：
- 主色调用我的品牌色#007bff
- 圆角12px（更大）
- hover时不要背景渐变，只要加深

请生成符合要求的代码。"
```

## 💡 高级技巧

### 技巧1：先描述需求，再要代码

```markdown
# Step 1: 先确认理解

我要创建一个登录表单，需求如下：
[详细描述]

请你复述一遍我的需求，确认理解正确。

# Step 2: 生成代码

确认无误后，请生成代码。
```

### 技巧2：分模块生成

```markdown
# 先生成组件结构

"请帮我规划一个用户管理页面的组件结构：
- 页面布局
- 组件拆分
- Props定义
- 暂时不需要具体代码"

# 再生成具体组件

"基于上面的结构，请生成UserTable组件的代码"
```

```markdown
请生成代码，要求：

代码风格：
1. 使用函数组件 + Hooks
2. TypeScript严格模式
3. 命名：组件PascalCase，变量camelCase
4. 每个函数有JSDoc注释
5. 复杂逻辑有行内注释

代码结构：
- Imports
- Types/Interfaces
- Constants
- Component
  - Hooks
  - Handlers
  - Effects
  - Render
- Export
```

## 🚫 常见错误

### ❌ 错误的描述方式

1. **太模糊**
   - ❌ "做一个好看的按钮"
   - ✅ "做一个蓝色圆角按钮，hover时背景变深"

2. **信息不足**
   - ❌ "创建一个表单"
   - ✅ "创建一个登录表单，包含邮箱和密码字段"

3. **前后矛盾**
   - ❌ "用Flex布局，但是要用Grid"
   - ✅ "用Flex布局实现横向排列"

4. **一次要求太多**
   - ❌ "创建一个完整的电商网站（首页、列表、详情、购物车、支付...）"
   - ✅ "先创建商品卡片组件，然后再做列表页"

### ✅ 正确的描述方式

1. **具体明确**
   - 说明颜色值、尺寸、间距
   - 说明交互行为
   - 说明技术栈

2. **分步骤**
   - 先布局，再样式，最后交互
   - 先组件，再页面

3. **提供参考**
   - 参考设计稿图片
   - 参考其他组件库
   - 参考类似代码

## 🎯 快速参考

### 描述需求Checklist

描述需求前，确认是否包含：
- [ ] 组件类型（按钮/表单/卡片等）
- [ ] 功能需求（能做什么）
- [ ] 样式需求（长什么样）
- [ ] 交互需求（如何交互）
- [ ] 技术栈（用什么技术）
- [ ] 输出格式（代码+示例+说明）

### 优化PromptChecklist

当AI生成不满意时：
- [ ] 哪里不符合预期？（具体指出）
- [ ] 我是否描述清楚了？（补充信息）
- [ ] 是否需要提供参考？（图片/代码）
- [ ] 是否应该分步骤？（降低复杂度）
