# 综合下来错误的原因是
有区别，而且**区别就那一根“刺”**：你上面报错的那条里，`app_token` 后面被**插进了一段 URL-encode 的 JSON**（就是那串 `%22%2C%22table_id%22%3A%22...`）。

---

## 1）两条 curl 的唯一区别（精确指出）

### ✅ 你这条（正常的 URL）

```text
.../apps/SpqObpOGNaLLTosblBjcRpJfnbf/tables/tblkzweAFbL32Ulm/records/recv9yJnjice97
```

### ❌ 你上面报错那条（坏掉的 URL）

```text
.../apps/SpqObpOGNaLLTosblBjcRpJfnbf%22%2C%22table_id%22%3A%22tblkzweAFbL32UIm/tables/...
```

**差的就是这段：**

```text
%22%2C%22table_id%22%3A%22tblkzweAFbL32UIm
```

---

## 2）那根“刺”到底是什么（为什么会让它报错）

把它 URL decode 一下就是：

```text
","table_id":"tblkzweAFbL32UIm
```

翻译成人话：

> 你的 `app_token` 被当成了  
> `"Spq...","table_id":"tbl..."`  
> 这种“拼接过的字符串/对象”，然后又被 URL 编码了。

所以飞书收到的路径变成了：

- app_token = `Spq...","table_id":"tbl...`（这是非法的）
    
- 路由当然匹配不上 → 必炸
    

---

## 3）为什么同样看起来你填的是 app_token，最后却变成了 encode 乱码？

这说明**不是你手写 curl 的问题**，而是你用的“插件/自动生成 curl”的地方，把 **app_token 这个字段**喂成了：

- 一个对象（包含 table_id）
    
- 或一个 JSON 字符串
    
- 或从上游节点映射了“整坨 JSON”
    

然后系统为了放进 URL path，做了 `encodeURIComponent()`，就出现 `%22 %2C %3A`。

---

## 4）你这条“正常 URL”的 curl 如果还是报错，下一步该看什么？

既然 URL 已经正常了，那剩下的报错只可能来自下面三类（按概率从高到低）：

### A. token 权限/有效期问题（最常见）

- token 过期
    
- token 不是这个多维表格所属租户的
    
- 没给 bitable 权限范围（scope）
    

### B. record_id 不存在 / 属于别的表

- `recv9yJnjice97` 不在 `tblkzweAFbL32Ulm` 这个表里
    

### C. 字段名不匹配 / 字段类型不支持这样写

- 你的列名不是完全等于 `企业参考链接`（可能多了空格/全角符号）
    
- 列类型是“超链接/多值/附件”等，写入格式要求不同
    

---

## 5）你现在最需要给我的是：**“飞书返回的报错 body”**

你别只贴 curl 了，curl 只是请求。关键是飞书返回什么。

你用这一条把返回打印出来（会把 code/msg 打出来）：

```bash
curl -i -X PUT "https://open.feishu.cn/open-apis/bitable/v1/apps/SpqObpOGNaLLTosblBjcRpJfnbf/tables/tblkzweAFbL32Ulm/records/recv9yJnjice97" \
  -H "Authorization: Bearer t-g10422087JMAZZXSF57IV7GVNPZJNNGMLMTWGSC6" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"fields":{"企业参考链接":"https://www.tianyancha.com/nsearch?key=浙江字节跳动科技有限公司\nhttps://www.tianyancha.com/nsearch?key=天津字节跳动科技有限公司\nhttps://www.tianyancha.com/nsearch?key=福建字节跳动科技有限公司"}}'
```

然后把返回里的这三行贴我就行（打码 token 无所谓）：

- HTTP 状态码（200/400/401/403/404）
    
- `code`
    
- `msg`
    

---

### 你问“区别是那根？”——答案就是：

> **区别就是 URL 里有没有那段 `%22%2C%22table_id%22%3A%22...`（把 JSON 插进了 app_token）**。  
> 有它必错；没有它，才进入“权限/record_id/字段名”层面的真实问题。
