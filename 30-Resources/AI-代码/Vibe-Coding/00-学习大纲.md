### 📂 文件位置：`03-VibeCoding实战/`

#### 5.1 Vibe Coding 核心理念

> **"完全沉浸于编程的'氛围'中，忘记代码的存在"** —— Andrej Karpathy

**核心定义**：用自然语言描述需求，让 AI 生成代码，开发者专注于意图和效果而非语法细节。

#### 5.2 主流工具对比

| 工具 | 定位 | 适用人群 | 特点 |
|------|------|---------|------|
| **Cursor** | AI 驱动的 IDE | 技术开发者 | 功能最全，支持复杂项目，需理解代码结构 |
| **v0 by Vercel** | 前端生成工具 | 非技术用户 | 最易上手，组件丰富，Vercel 集成好 |
| **Lovable** | 全栈生成平台 | 零基础小白 | 极低门槛，自动集成后端，免费额度友好 |
| **Bolt.new** | 全栈 AI IDE | 团队/快速原型 | 实时协作，一键部署，功能全面 |
| **Replit** | 在线 IDE + AI | 教育/初学者 | 在线运行，支持多语言，Agent 模式 |
| **Claude Code** | AI 命令行工具 | 技术开发者 | 基于 Claude Sonnet，代码能力强 |

#### 5.3 系统化学习资源

| 资源 | 类型 | 链接 |
|------|------|------|
| **程序员鱼皮 - Vibe Coding 零基础教程** | 免费完整教程 | https://ai.codefather.cn/vibe |
| | GitHub 开源 | https://github.com/liyupi/ai-guide |
| **Datawhale - Vibe Vibe 教程** | 系统化开源教程 | https://www.vibevibe.cn |
| | GitHub | https://github.com/datawhalechina/vibe-vibe |

#### 5.4 Vibe Coding 工作流程

```
1. 意图描述（自然语言）
    ↓
2. AI 生成代码
    ↓
3. Vibe Check（效果验证）
    ↓
4. 自然语言迭代
```

#### 5.5 核心技巧
- **提示词工程**：Context is King，提供足够上下文
- **MVP 思维**：先做出能跑的最小版本
- **用户旅程地图**：把想法变成 AI 能理解的路径
- **PRD 文档**：让 AI 不再胡编乱造

## 第七阶段：Debug - 调试技巧 Mastery

### 🎯 学习目标
- 掌握系统化调试流程
- 熟练使用调试工具
- 建立问题排查思维

### 📂 文件位置：`05-调试Debug/`

#### 7.1 调试方法论

| 方法 | 适用场景 | 技巧 |
|------|---------|------|
| **print 调试法** | 简单问题、快速验证 | console.log 关键变量 |
| **IDE 断点调试** | 复杂逻辑、多函数嵌套 | Step Over/Into/Out |
| **日志记录** | 生产环境、异步问题 | logging 模块分级记录 |
| **单元测试** | 隔离验证代码片段 | Jest/Mocha 测试框架 |

#### 7.2 VS Code 调试技能

```
1. 打断点（点击行号左侧）
2. 点击 Debug 按钮（绿色虫子图标）
3. 查看变量面板
4. 单步执行：F8(Step Over) / F7(Step Into) / F9(Continue)
```

#### 7.3 系统化 Debug 流程

1. **问题复现** - 确定错误发生的条件和频率
2. **缩小范围** - 注释代码或分段测试定位错误位置
3. **假设验证** - 提出可能原因，逐一验证或排除

#### 7.4 进阶技巧
- **条件断点** - 特定条件下触发断点
- **内存分析** - 检测内存泄漏（Valgrind 等）
- **远程调试** - 针对服务器上的应用

## 第八阶段：Code Review - 代码审查最佳实践

### 🎯 学习目标
- 理解代码审查的价值
- 掌握审查流程和标准
- 能够给出建设性反馈

### 📂 文件位置：`06-代码审查/`

#### 8.1 代码审查核心原则

| 原则 | 说明 |
|------|------|
| **功能正确性** | 代码是否按预期工作？ |
| **软件设计** | 架构是否合理？ |
| **复杂度** | 其他开发者能否轻松理解？ |
| **测试覆盖** | 是否有正确的自动化测试？ |
| **命名规范** | 变量、函数名是否描述清晰？ |
| **注释文档** | 注释是否清晰有用？ |

#### 8.2 审查流程最佳实践

1. **自动化预检** - 提交前运行代码质量检查
2. **控制代码量** - 每次审查 < 400 行代码
3. **小步快跑** - 频繁的小审查优于大规模审查
4. **明确反馈** - 使用 "Request changes" 等明确标识
5. **建设性态度** - 关注代码改进而非个人批评

#### 8.3 审查清单（Checklist）

```
☐ 单元测试已提供
☐ 代码格式正确（Linting 通过）
☐ 命名规范合适
☐ 无安全漏洞
☐ 无重复代码
☐ 注释清晰
☐ 文档已更新
```

#### 8.4 AI 辅助代码审查
- **Claude Code** - 自动化代码检查、智能代码解释
- **GitHub Copilot** - 代码建议和质量提示
- **SonarQube** - 静态代码分析
