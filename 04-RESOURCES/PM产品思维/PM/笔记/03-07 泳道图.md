### 第一部分：正常业务流程图模板（参考案例）

**说明：** 此模板基于视频中“招投标/发单平台”的案例整理。

#### **图表标题：招投标业务泳道流程图**

**1. 涉及角色（泳道）：**
*   **业主（需求方）**
*   **师傅/服务商（承接方）**
*   *(可选) 平台（系统/中介）*

**2. 流程节点详情：**

| 步骤 | 角色 | 动作/节点描述 | 备注/逻辑 |
| :--- | :--- | :--- | :--- |
| **Start** | **业主** | **开始** | 流程起点 |
| 1 | 业主 | 编辑/发布招标任务 | |
| 2 | 业主 | 支付费用给平台 | 前置条件，支付后任务可见 |
| 3 | *(平台)* | *任务展示/发布成功* | *若不加平台泳道，可省略或合并至业主节点* |
| 4 | **师傅** | 浏览任务 | |
| 5 | 师傅 | **投标** | 多个师傅可投标，流程图中只需画一个代表 |
| 6 | **业主** | **选择中标师傅** | 从投标者中挑选 |
| 7 | 师傅 | **中标** | 逻辑判断：是否中标？<br>→ 否：继续投标其他任务（循环）<br>→ 是：进入下一步 |
| 8 | 师傅 | 线下施工 | |
| 9 | 师傅 | 施工完成，线上申请验收 | |
| 10 | **业主** | **线下验收** | |
| 11 | **业主** | **验收判定** | **关键决策点（菱形）** |
| 11-A | 业主 | 验收通过 | 路径 → 步骤 12 |
| 11-B | 业主 | 验收驳回 | 路径 → 返回 步骤 8 (重新施工) |
| 12 | *(平台)* | *平台打款至师傅账户* | 资金结算 |
| 13 | 师傅 | 账户收款 | 资金在平台账户内 |
| 14 | 师傅 | 申请提现 | |
| 15 | 师傅 | 提现成功至银行卡 | |
| **End** | **师傅** | **结束** | 流程闭环 |

**3. 绘制要点提示：**
*   **泳道划分：** 左侧或顶部列出角色，确保每个动作都落在对应的角色列内。
*   **异常流程：** 必须包含“验收不通过”的回退循环逻辑。
*   **简化处理：** 不需要画出所有投标的师傅，用一个“师傅”泳道代表所有承接方即可。


### 第二部分：抽象出来的流程图制作方法论

#### **一、核心概念认知**
1.  **泳道图（Swimlane Diagram）定义：**
    *   在普通流程图基础上，通过“泳道”将不同角色（部门/人员）的动作进行物理隔离。
    *   **核心价值：** 清晰展示“谁在什么阶段做了什么”，明确责任边界。
#### **二、制作四步法**
**Step 1：角色梳理（定泳道）**
*   **动作：** 列出所有参与业务流程的角色。
*   **原则：**
    *   至少包含发起方和接收方（如：买家/卖家，业主/师傅）。
    *   根据复杂度决定是否加入“平台/系统”作为独立角色。若系统动作较少，可合并到相关角色中；若系统交互复杂，建议独立泳道。
*   **产出：** 确定泳道数量及名称。
**Step 2：动作归位（填内容）**
*   **动作：** 将业务过程中的每一个具体步骤，分配到对应的角色泳道中。
*   **原则：**
    *   **谁做谁负责：** 动作必须画在执行该动作的角色泳道内。
    *   **线上/线下区分：** 明确哪些是系统操作（线上），哪些是人工操作（线下），可在节点文字中备注。
*   **产出：** 散落在各泳道中的独立节点。
**Step 3：逻辑连接（连线条）**
*   **动作：** 使用箭头将节点按时间顺序连接，并处理逻辑分支。
*   **关键逻辑处理：**
    *   **顺序流：** 正常步骤依次连接。
    *   **判断流（菱形）：** 遇到“是否通过/是否中标”等判断，需画出 Yes/No 两条分支。
    *   **循环流（闭环）：** 对于“驳回/不通过”的情况，箭头应指回之前的修改/重做节点，形成闭环，**切忌流程中断**。
    *   **多对一简化：** 如多个师傅投标，无需画多个泳道，用一个代表角色即可，通过文字说明“多人投标，一人中标”。
**Step 4：美化与审查（优细节）**
*   **动作：** 调整布局、对齐、检查逻辑漏洞。
*   **检查清单：**
    *   **闭环检查：** 所有流程是否有终点？异常流程是否有出口？
    *   **对齐美化：** 利用工具（如 ProcessOn、Visio）的“一键美化”或手动对齐，保持视觉整洁。
    *   **粒度控制：** 步骤颗粒度要统一，不要一步写“开发”，下一步写“点击保存按钮”。
#### **三、避坑指南（基于视频经验）**
1.  **不要过度复杂化：** 如果流程中涉及 10 个师傅投标，不要画 10 个分支，抽象为“投标 -> 判定是否中标”即可。
2.  **角色边界清晰：** 严禁一个节点跨两个泳道，如果涉及交互，拆分为两个节点（如：业主验收 -> 系统记录结果）。
3.  **资金流明确：** 涉及钱的流程（如充值、打款、提现），要明确资金在哪个账户（平台账户 vs 个人银行卡），这通常是流程的关键卡点。
4.  **异常流程优先：** 新手容易只画“快乐路径”（一切顺利），必须重点思考“如果验收不通过怎么办？”、“如果流标怎么办？”，这才是流程图的价值所在。
