## Text Elements
07 泳道图的绘制 - 角色维度的流程图 ^title

📊 泳道图定义 ^definition

泳道图 = 流程图 + 角色维度

核心特点：
• 按角色划分流程区域
• 每个角色负责自己的流程步骤
• 更清晰地展示多人协作 ^definition-content

🎯 简单案例：商场购物 ^simple-case

角色1：买家
• 进商场
• 挑选商品
• 付款
• 收取商品
• 收取发票（可选）
• 离开

角色2：卖家
• 收款
• 开具发票
• 打包商品
• 交付商品 ^buyer-seller

🏠 复杂案例：装修平台招投标 ^complex-case

角色1：业主
1. 编辑发布竞标任务
2. 支付费用给平台
3. 任务发布成功
4. 选择指定师傅（中标）
5. 线下验收
6. 确认通过（付款给师傅）
   或 拒绝（返回施工）

角色2：师傅
1. 浏览任务
2. 投标
3. 是否中标？
   ├─ 是 → 开始施工
   │      ├─ 申请验收
   │      └─ 验收通过
   └─ 否 → 继续投标其他任务
4. 收到款项
5. 申请提现 ^platform-case

🎨 ProcessOn绘制泳道图 ^drawing-guide

步骤1：添加泳道
• 左侧工具栏 → 泳道元素
• 拖拽到画布
• 设置泳道数量（2个或更多）

步骤2：命名角色
• 在泳道顶部输入角色名称
• 如：业主 | 师傅
• 可加粗突出显示

步骤3：绘制流程
• 在对应角色泳道内添加流程节点
• 跨泳道连线表示角色间交互
• 使用判定菱形表示条件分支 ^drawing-steps

💡 核心要点 ^key-points

• 泳道图本质：在流程图基础上增加角色维度
• 适用场景：多人协作的复杂业务流程
• 分类：业务泳道图、功能泳道图皆可
• 绘制原则：每个角色的操作划入自己的泳道区域
• 优点：清晰展示责任分工，便于流程优化

⚠️ 注意事项 ^notes

• 不要重复绘制相同角色的流程
• 例如：10个师傅投标，只需画一个"师傅投标"节点
• 通过判定区分：中标 vs 流标
• 泳道数量建议：2-4个角色最佳
