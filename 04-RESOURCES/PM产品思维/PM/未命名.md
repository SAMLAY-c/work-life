# 需求分析【20-23】
```text
原始需求 → [角色] → [场景] → [目的] → 产品方案
```
### 1. 角色（Who）
**定义：** 需求的发起方与相关利益方

| 维度         | 关键问题                   | 示例（直播间案例）     |
| :--------- | :--------------------- | :------------ |
| **角色关系**   | 他们之间如何互动？              | 1v1教学 或 1v多教学 |
| 区分提出者vs使用者 | 外教提的需求，可能源自学生痛点        |               |
| 多角色并列分析    | 如直播间：老师（教学）、学生（学习）需求不同 |               |
| 角色画像细化     | 身份、能力、使用习惯、痛点预判        |               |

✅ 输出：角色清单 + 各角色核心诉求假设
**要点：** 同一功能，不同角色的使用方式和出发点完全不同。
### 2. 场景（Where/When/What）
**定义：** 用户在什么情况下，做了什么事，遇到了什么阻碍
**场景的描述公式：**
> 「在 [特定环境] 中，当 [用户状态] 时，想要 [完成某事]，但因 [现有局限] 导致 [具体痛点]」
**示例：**
> 在直播上课过程中，当学生听到不懂的知识点时，想要立即提问答疑，但因没有文字输入功能，只能憋着无法反馈。
- **如何提炼场景（方法论）**：
1️⃣ 产品沉浸：亲自使用产品，建立真实认知
2️⃣ 换位思考：「如果我是TA，此刻会怎么做？」
3️⃣ - **模拟流程**：模拟用户从“开始”到“结束”的全过程。
            - _案例推演_：老师上班 -> 打开网页登录 -> 开摄像头 -> 打开PPT -> 开始讲课 -> 发现学生听不懂 -> 需要互动/答疑。
4️⃣ 头脑风暴：穷举可能的使用情境（定性）
- **场景与功能的关系**：
    - 一个场景可能对应一个目的。
    - 多个场景可能最终对应同一个目的（此时一个功能即可解决多个场景问题）。
### 3. 目的（Why）
- **定义**：用户在做这件事时，最终想要达到的效果是什么。
- **关键逻辑**：
    - **目的必须挂钩场景**：单纯问“目的是什么”容易跑偏，必须结合具体场景来问。
    - **区分“方案”与“目的”**：
        - 用户提的往往是“方案”（如：我要打字功能）。
        - 产品经理要挖掘的是“目的”（如：为了实时答疑）。
        - **关键原则**：目的必须从场景中推导，避免脱离情境空想

| 表面需求     | 可能隐藏的真实目的         |
| -------- | ----------------- |
| 「加个打字功能」 | 学生想即时提问，不打断教学节奏   |
| 「加个举手按钮」 | 一对多场景下有序互动，避免语音混乱 |
| 「邀请语音功能」 | 增强互动感/进行口语练习/确认理解 |

✅ 输出：每个场景对应的核心目的（用「为了…」句式表达）

# 有没有必要做--怎么做
那就是考虑说需求有没有必要去做，可以从两个方向去考虑，一个是从主观上所涉及到的所有人员，比如说一个需求涉及到了课程，那么就要去调查老师跟学生这两个部分，他们两个人是不是都有相应的印象，第二个是在客观上需不需要做，客观上加了这个功能之后，对于这个环节里面的其他功能可能会带来一些蝴蝶效应的影响，然后这个是需不需要做，第二个就是探讨功能实现的路径是怎么样的，去设计这个功能，所以说第一个是分析这个需求值不值得做，分析这个需求值不值得做分这两部分，一个是主观部分，一个是客观部分
